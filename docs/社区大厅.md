# 比赛公告与约玩大厅

OPP 核心功能区提供“比赛公告”和“约玩大厅”两个入口。保留现有 osu! 登录流程，浏览这些页面无需连接社区身份；发布和管理约玩信息共用 BeatmapHub 的设备认证与会话续期。

## 浏览与发布

比赛公告使用海报瀑布流，支持关键词、模式、状态筛选。点击卡片查看主办方、报名和比赛时间、参赛要求、文字介绍与外部报名入口；无海报或图片加载失败时显示占位图。客户端不提供赛事发布表单，主办方加入 QQ 群 **1059437719** 联系管理员录入。

OPP 合作赛事 ASC 星域杯 S2（Astracup）通过 VPS 正式比赛公告录入，与其他赛事共用搜索、筛选和详情，不在客户端额外插入本地示例。官网公开资料的录入内容见 [astracup-s2.json](./community/astracup-s2.json)，来源与核对说明见 [星域杯 S2 资料](./community/astracup-s2.md)。未公布的报名及比赛日期允许为 `null`，客户端显示“待公布”，服务器将未开始且未公布日程的赛事归为 `upcoming`，默认列表可见。

约玩大厅使用小卡片瀑布流，支持关键词、模式、活动类型和平台筛选。约 MP、约战、排位找搭子、一起练图和其他活动共用表单；平台可选择普通 osu!、RomAI、Vash Esports、osu! ranked lobbies、其他，或不指定。平台只是活动说明，不接入这些平台的匹配 API。

详情展示完整描述、开始/结束时间、发布者 osu! 用户名与数字 ID，提供复制 ID 和打开个人主页。玩家自行联系发布者；首版不记录报名成员、人数，不提供站内聊天。

发布时自动带入当前 osu! 身份，标题与描述必填，最多分别为 120 和 2000 字。时间按本地时区填写，发送 UTC 时间；结束时间须晚于开始及当前时间，允许发布正在进行的活动。首次连接或认证恢复保留草稿，连接完成后再次点击确认才发布。

发布即公开，默认列表只显示未结束信息。到期由 VPS 时间判定，无需定时写回数据库。客户端参考服务器时钟更新约玩状态，并在页面打开期间定期刷新。作者可在“我的发布”查看历史、编辑未结束信息、提前结束或删除；已经结束的活动不能重新开放。

## 架构与权限

前端 `community` feature API → typed Tauri adapter → Rust community service → VPS。社区 feature 使用公开 transport 能力共享现有认证，不读取 BeatmapHub 内部状态。旧命令和认证响应契约保持兼容。

服务端新增 `community_tournaments`、`community_lobbies`，沿用现有 PostgreSQL、Drizzle、JWT 及权限机制。公开读取不要求 Bearer token；约玩写入使用 `packhub:publish`/`packhub:edit`，管理员管理使用 `packhub:admin`。编辑所有权取自内部 `packhub_user_id`，不以展示的 osu! ID 为依据，也不自动按相同 osu! ID 合并设备。当前 osu! 身份是客户端声明，不展示官方身份验证徽标。

所有接口以 `/api/v2/community` 开头。公开赛事和约玩均提供列表及详情；约玩另有 `/lobbies/mine`、创建、修改、提前结束和软删除接口；管理员通过 `/admin/tournaments` 管理赛事，并通过 `/admin/lobbies/:id` 下架信息。列表默认 20 条，最多 50 条，采用服务端搜索、倒序排列和微秒精度游标，返回 `items`、`next_cursor`、`server_time`。

接口字段、管理员录入样例及 PostgreSQL 测试步骤见服务端仓库 `docs/community-api.md`。赛事正文为纯文字，海报只保存 HTTPS URL；无上传服务。日志不记录令牌、私钥或请求正文。

## 发布顺序

先备份并迁移 VPS 数据库，再上线兼容接口和确认公开读取可用，最后发布 OPP。升级不会改变现有 BeatmapHub 数据及 API，回退客户端时保留新增数据库表。浏览器开发预览使用内存示例数据，不访问 VPS；桌面端始终使用真实服务。

Windows 和 Linux 需要分别验收页面、弹窗、外部链接、时区和身份续期；浏览器及自动化检查不能替代 Linux 桌面实机验收。
