# 本地数据库与索引迁移

本地数据库提供位置设置、SQLite 建表、版本迁移和恢复入口，现在也保存现有本地资源索引，支持自动导入旧 JSON、数据库优先读取和扫描后的事务增量写入。在线谱面通过批量查询显示本地已有状态。现有内存查询、游戏文件监听和相似谱面数据集保持兼容；不会迁移相似数据集、账号凭据或采集生涯数据。

## 保存与生命周期

- 默认目录为 Tauri 应用数据目录中的 `datasets`；首次启动可选其他本机目录，也可跳过。跳过仅作用于本次启动。
- 目录内创建 `library.sqlite3`，仅用于可重新生成的索引。SQLite 自行管理同目录内的 `-wal`、`-shm` 文件，不能在数据库打开时单独删除或复制这些文件。
- 应用数据目录的 `local-database.json` 保存配置版本、规范化绝对目录和数据库 UUID。写入使用临时文件、文件同步、替换及备份；启动可恢复主文件缺失但备份完整的中断状态。配置损坏不会回退为首次配置。
- 数据库在后台 IO 工作池打开，单个连接由服务 mutex 保护。创建、恢复及查询配置串行执行；现阶段没有通用 SQL 前端接口。
- 正常数据库暂不支持搬迁。路径失效时保留配置，可重试或重新定位 UUID 相同的原数据库；不会静默创建空库。
- 初始化失败不覆盖已有文件。数据库已创建但配置写入失败时保留数据库，允许选择同一目录重试。磁盘离线、权限错误、损坏及较新 schema 均允许暂时跳过，其他功能仍可用。

## SQLite 约定

主程序和相似谱面运行库统一使用 `rusqlite =0.39.0`、`libsqlite3-sys 0.37.0`，bundled SQLite 为 3.51.3；锁文件固定依赖，运行时拒绝低于 3.51.3 的 SQLite。

索引库启用 `journal_mode=WAL`、`foreign_keys=ON`、`busy_timeout=5000`、`synchronous=NORMAL`、`wal_autocheckpoint=1000`。正常退出关闭连接，由 SQLite 执行最终 checkpoint。WAL 仅支持本机文件系统：Windows 拒绝 UNC 和映射网络盘；Linux 拒绝识别到的常见网络挂载。检查不能保证识别所有第三方文件系统，应选择本机磁盘上的普通目录。

使用 `application_id=0x4f50504c`（OPPL）、`user_version`、用途 `opp_local_library` 和 UUID 校验身份。现有文件必须先通过身份检查，才允许设置 WAL 或执行迁移；较新版本不降级。迁移按顺序执行，DDL、迁移记录和版本更新在同一事务中提交，失败整体回滚。

初始化状态 `ready` 仅代表数据库可用，不能推断“已经扫描”或“本机没有某张谱面”。

正常启动只校验身份、版本、表/索引结构及写入能力，不进行全库完整性扫描，避免未来索引增大后每次启动产生线性 IO。首次接入已有数据库、显式重新定位原数据库时执行 `quick_check`；其他数据页损坏由 SQLite 在实际访问时报告。

## Schema v1

SQL 定义位于 `src-tauri/src/infrastructure/local_database/schema_v1.sql`。

| 表 | 内容及约束 |
| --- | --- |
| `database_meta` | 单例行：UUID、UTC 创建时间、用途 |
| `schema_migrations` | 迁移版本主键及 UTC 应用时间 |
| `library_sources` | 客户端、规范化根目录、最近成功扫描时间、完整度；客户端与根目录联合唯一 |
| `beatmap_files` | 数据源外键、源内标识、物理/逻辑路径、大小、修改毫秒、内容哈希、谱面 MD5；数据源与源内标识联合唯一 |
| `beatmap_metadata` | 文件外键主键、可空在线谱面/谱面集 ID、模式、标题及 Unicode 标题、作者及 Unicode 作者、制图者、难度名称 |

在线 ID 和 MD5 不唯一，支持未上传谱面、同内容重复副本和 Stable/lazer 多来源共存。MD5、谱面 ID、谱面集 ID 有独立索引；联合唯一索引同时支持按来源查找文件。文件与元数据分离，未来 Stable 可用路径定位，lazer 可用源内标识及内容哈希定位。大小和修改时间使用非负 SQLite INTEGER；时间戳为毫秒，UTC 时间为 RFC3339 文本。

不持久化音频、背景、回放等大文件、成绩或账号凭据。不会把完整旧 JSON 索引放进单个数据库字段。

## 接口

`get_local_database_status` 返回阶段、配置目录、推荐目录、UUID、可用 schema 版本、`can_initialize` 和错误。`can_initialize=false` 时不能创建新库，包括配置损坏及已有配置但库不可用。

`initialize_local_database(directory)` 创建首次数据库或接入已有有效 OPP 索引库；同目录重复初始化幂等，已配置其他目录则拒绝。`retry_local_database` 重新加载位置配置并打开；`locate_local_database(directory)` 仅在原库不可用时接入 UUID 相同的文件，不创建文件。

前端通过 typed command adapter 和 TanStack Query 接入；启动 gate 处理完成或跳过之后才挂载登录与页面引导。设置中的“本地数据”提供初始化及恢复入口。浏览器预览固定返回模拟可用状态，不访问磁盘。

## Schema v2 与迁移

v1 自动事务升级到 v2，保留数据库 UUID 和已有记录。新增：

| 表／字段 | 内容 |
| --- | --- |
| `resource_entries` | 按数据源和源内标识唯一，每个资源条目独立 JSON 与 SHA-256；保留原有分析结果、皮肤清单、lazer 内容定位与诊断信息 |
| `beatmap_files.resource_entry_id` | 可空资源条目外键及唯一索引，删除条目级联删除谱面文件与元数据 |
| `library_snapshots` | 每个客户端的活动来源、索引 schema、难度算法版本、汇总、诊断、扫描版本与资源条目数 |

打开数据库后优先加载兼容快照，只在数据库没有可用快照或读取失败时读取旧 `{client}-index.json`；兼容的 JSON 会自动导入数据库。首次初始化、重试打开及重新定位成功后，也会导入当前已加载的索引；如果最新索引只在曾经离线的数据库中，恢复后会自动载入尚未恢复到内存的客户端快照。导入只读取已有索引，不扫描 `.osu`、不启动新的扫描任务。

扫描流程继续复用原有大小、时间戳和内容哈希判断。保存时按条目 SHA-256 对比，只插入新增项、更新变化项和删除移除项；快照、资源、文件定位与元数据在同一事务中提交，失败回滚。Stable/lazer 使用独立来源，不以在线 ID 或 MD5 去重。切换客户端根目录后的新扫描替换该客户端的活动快照。

数据库保存失败时保留错误并回退到 JSON，原 JSON 在数据库成功保存时保留、不再全量重写。缓存目录中的 `{client}-index-revision.json` 在持久化前记录预期扫描版本，避免数据库写入失败后重启优先选择旧数据库；也避免最新数据库失效时重新载入较旧 JSON。没有匹配最新版本的可用索引时需要恢复数据库或重新扫描。版本记录使用临时文件、同步和备份替换；损坏不会静默接受旧索引。

索引兼容性同时检查 schema 与难度算法版本；SQL 读取使用一致性事务，恢复时校验条目哈希和数量。内存中的资源查询索引仍在启动时重建；本次没有实现整个本地库的 SQL 懒分页。IO 改善主要来自避免成功扫描后全量重写 JSON，以及在线标记查询不逐张打开 `.osu`。仍需在真实大库上测量冷启动、扫描持久化耗时和实际写入量，不能承诺固定加速倍数。

## 在线已有状态与设置

新增 `query_local_beatmap_presence(ids, client)`：最多 1000 个输入 ID，去重正 ID；客户端可选 Stable、lazer 或两者。前端只查询当前可见搜索结果、热门列表和当前详情，以批次调用，超出限制拆批，不逐卡片发送命令。

先校验当前来源可访问且根目录与索引一致；数据库快照版本与内存索引一致时用在线 ID 索引查询，否则使用已有内存 ID 查询索引。任一有效来源命中即为 `present`；只有有效完整索引且没有未扫描、不可访问、扫描中、待扫描或失败来源时才返回 `missing`，其他情况为 `unknown`。解析/读取/发现错误也使缺失项保持未知。来源未安装时不参与否定判断，完全没有可用索引时返回未知。

本地状态复用 Ranked 旁的状态徽标组件与样式，包含图标、边框和背景，并适配浅深主题。曲包所有难度命中才显示“本地已有”，部分命中显示“部分已有 x/y”；具体难度显示所属客户端。未知不会被显示为缺失。匹配按谱面 ID，不验证在线 MD5，旧版本或同 ID 修改文件也可能命中；标记不会禁用下载和打开操作。文件监听更新扫描版本后刷新标记，空闲时每 5 秒刷新当前可见状态。

设置 → 本地数据：集中提供数据库位置、版本与状态，各客户端的持久化介质、谱面/资源数量、索引更新时间和错误、索引导入／同步、Stable 和 lazer 的增量扫描更新、标记开关（默认开启）及匹配客户端（默认两者）。异常时可重新打开数据库并同步；游戏安装路径仍在“游戏目录”中配置。新增 `get_local_library_storage_status` 与 `migrate_local_library_database`；前端不提供 SQL 接口。浏览器预览返回固定未知／未扫描状态，不访问磁盘。

## 后续边界

未来在同一目录创建独立 `career.sqlite3`，使用自己的 schema、迁移、备份和保留规则；不能被索引清理或重建操作影响。需要明确账号身份、游戏模式、采集来源、UTC 采集时间、所属本地日期和当时的时区，并区分原始记录与每日汇总。具体指标、表结构和采集时机在生涯功能阶段确定。历史库的持久化等级与备份要求独立制定。

凭据继续存放在现有系统凭据存储中。真实数据库、定位配置和用户数据不进入版本控制。
