# 弹窗与通知规范

OPP 的界面反馈分为两类：需要用户完成或确认的任务使用弹窗，不打断当前操作的结果反馈使用通知。功能代码不应再自行拼接全屏遮罩、固定定位通知或独立的 z-index。

## 弹窗

常规弹窗统一使用 `src/shared/components/AppDialog.tsx` 导出的 `AppDialog`：

```tsx
<AppDialog
  open={open}
  onOpenChange={setOpen}
  title="删除收藏夹"
  description="本地谱面文件不会被删除。"
  size="sm"
  footer={(
    <>
      <Button variant="ghost" onClick={() => setOpen(false)}>取消</Button>
      <Button variant="danger" onClick={remove}>删除</Button>
    </>
  )}
>
  <p>弹窗正文</p>
</AppDialog>
```

- `sm` 用于确认，`md` 用于表单，`lg` 用于信息较多的工作流。
- 标题必须描述动作或结果；说明文字只补充影响，不重复标题。
- 默认允许 Esc、遮罩和右上角关闭。不可中断的任务通过 `closeDisabled` 锁定关闭。
- 主操作放在右侧；取消使用 `ghost`，危险操作使用 `danger`。
- 抽屉、路由级大面板等特殊容器继续使用 Radix Dialog，但应复用 `src/shared/components/dialogStyles.ts` 的 `appDialogStyles` 遮罩、表面和层级，不创建新的视觉规范。

## 通知

简单结果使用 `src/shared/components/notifications.tsx` 导出的命令式接口：

```tsx
notification.success("保存完成", "设置已经应用。");
notification.error("保存失败", { description: error.message, duration: null });
notification.info("发现新版本", {
  action: { label: "查看", onClick: openRelease },
});
```

- `info` 用于中性状态，`success` 用于成功结果，`warning` 用于可恢复异常，`error` 用于失败。
- 普通通知默认 5 秒后消失；必须由用户处理的错误使用 `duration: null`。
- 标题保持简短，具体对象和原因放在 `description`。
- 需要展示进度、文件列表或取消按钮时使用受控的 `NotificationCard`，仍保留统一的颜色、图标、圆角、关闭按钮和可访问性语义。
- 同一结果只显示一次。下载完成等场景不得同时再创建第二个 Toast。

## 层级与可访问性

- 标准弹窗使用统一 Portal 层级，通知视口位于标题栏下方。
- `AppDialog` 自动建立 `dialog`、标题和说明关系。
- `NotificationCard` 的普通状态使用 `role="status"`，错误使用 `role="alert"`。
- 图标不能作为唯一信息来源；关闭和图标按钮必须提供可读标签。
