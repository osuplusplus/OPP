# 本地音乐播放器验收记录

日期：2026-09-16。没有提升发布版本。

## 使用与实现

本地谱面右上角提供播放面板。展开后可选择全部本地库、Stable、lazer、当前筛选结果或收藏夹，也可将当前难度加入队列。来源默认跨客户端、全部游戏模式；队列与后续浏览筛选互相独立。缺失收藏夹项目只提示数量。

音乐从头播放，原试听按钮使用同一服务从试听点播放。提供顺序、列表循环、单曲循环、随机四种方式，默认列表循环。随机一轮不重复，上一首使用历史。按有效谱面集 ID 合并；无 ID 时仅用相同谱面校验值确认同源；保留其他难度与另一客户端的备用音频。队列、位置、音量、播放方式保存，重启保持暂停。

Rust 持有唯一队列和流式音频引擎，界面提交资源引用；播放时再次检查文件是否仍处于允许目录。Windows SMTC 使用独立隐藏原生宿主，Linux 使用 MPRIS；媒体适配失败保留界面控制。

迷你入口独立构建，360×72，可拖动、取消置顶、展开至 420 高、恢复、收起到托盘及退出。新窗口就绪后才释放旧窗口。Windows 使用独立 WebView2 环境，让主界面的浏览器与 GPU 缓存退出。迷你界面只显示小尺寸静态封面，最多每秒两次进度事件；暂停或窗口隐藏时不发送周期进度。

自动扫描和无活动会话的游戏／OBS 监控暂停，闲置本地索引、皮肤缓存、相似度索引释放。下载、扫描、渲染、活动游戏／OBS 会话及收藏夹操作继续；需要主窗口的任务保留隐藏窗口，结束后再释放。恢复时重新加载索引及原来的页面、筛选和窗口尺寸。

## 自动化与 Windows 原生验收

- 前端：55 个测试文件，174 个测试通过。播放器测试覆盖来源、收藏夹、过期事件、浏览不干扰播放、展开／置顶／恢复、进度／音量、移除／清空，以及大队列异步分页保留滚动高度。
- Rust：176 个测试通过，7 个已有测试忽略。新增测试覆盖双库与无 ID 合并、多音频备用排序、同音频不同谱面集、收藏夹解析、路径边界、四种播放方式与随机历史、暂停恢复及损坏持久化数据。
- 原生发布构建：1000 个谱面集、2000 个难度；WAV、MP3、OGG、FLAC 流式解码、跳转、同集备用音频、损坏曲目跳过、快速切歌通过。
- 主界面销毁后，Windows 系统媒体会话的播放、暂停、下一首、上一首和歌名更新通过。
- 需在 Windows 实机复验置顶／取消置顶、迷你界面深浅主题切换、暂停状态下恢复完整界面，以及缩放为 125% 时 360×72 逻辑像素的视口和悬停控件。
- 20 次完整界面／迷你窗往返通过，播放保持连续；每轮稳定后均为 7 个进程，没有累积旧 WebView 进程。
- 最终发布构建补测：整队列损坏后停止、暂停取消较早的异步队列请求、前端任务期间保留主窗口并在完成后释放、收起到托盘后再次启动同一程序唤醒迷你窗，均通过。任务保护采用合成任务状态验证，没有把它替代为真实下载／渲染负载验收。
- 前端构建、Rust 格式检查和本次前端改动的 ESLint 检查通过。
- 全仓库 ESLint 仍被已有 `src/features/tools/OtdPanel.tsx:17` 的 `react-hooks/set-state-in-effect` 阻断。全仓库 Clippy `-D warnings` 仍报告共享 `CommandError` 的 `result_large_err` 及已有死代码等问题；未将这些全局检查标记为通过。

## 复测入口与尚未验证的边界

`scripts/music-player-smoke.mjs` 生成合成谱库、通过 CDP 控制独立验收实例、记录进程组数据和截图。它拒绝控制路径不含 `music-acceptance` 的程序。`scripts/music-player-media-smoke.ps1` 只控制名称和艺术家匹配合成测试曲目的系统媒体会话。

Windows 独立验收构建使用 `TAURI_CONFIG={"identifier":"com.opp.music-acceptance-data"}`、`cargo rustc --release --features tauri/custom-protocol`，输出至 `src-tauri/target/music-acceptance/`。启动时设置 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=0`，将独立配置目录映射至该目录下的 `app-data`，然后运行 `node scripts/music-player-smoke.mjs 0 <独立实例PID> 20`。结果在忽略提交的 target 目录中，应用数据及凭据不纳入提交。

Linux 的音频输出、MPRIS、窗口管理器置顶／拖动及托盘行为尚未在 Linux 实机验证。Windows 多显示器拔插／混合 DPI、真实下载和渲染负载连续性、故意制造窗口创建失败／就绪超时、硬件媒体键及长时间播放仍需人工验收。代码中的屏幕工作区约束、15 秒切换回退、媒体会话与后台任务保护不能代替这些实机结果。
