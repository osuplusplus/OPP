# osu-difficulty-runtime

Read-only OPP runtime for datasets produced by
[`osu-difficulty-lab`](https://github.com/osuplusplus/osu-difficulty-lab).

This crate contains the compatible analyzer, normalizer and HNSW reader only.
It intentionally contains no dataset, downloader, importer, training pipeline,
or export tooling. Dataset directories are opened read-only and are never
modified by this crate.

## osu!mania Analyzer v1

The isolated Mania runtime is pinned byte-for-byte and formula-for-formula to
[`osu-difficulty-lab` commit `1fa21fa6`](https://github.com/osuplusplus/osu-difficulty-lab/commit/1fa21fa6a5144992df58efe7ce9d96019981fad3),
Analyzer snapshot `1:mania-roxy-interlude-similarity-v1`. It supports NoMod
4K, 6K, and 7K maps only. Its same-key-count ranked difficulty percentile is
a corpus-relative normalization value, not the official osu! star rating.

`ManiaDataset` requires exactly the v1 runtime artifacts
`mania-metadata.sqlite`, `mania-features-v1.bin`,
`normalizers/mania-v1.bin`, `indexes/mania-v1.buckets`, and its `.sha256`
checksum. SQLite is opened with `mode=ro&immutable=1`; the crate does not ship
or expose the upstream writable feature-store, importer, fitting, index-build,
CLI, or export pipeline. The obsolete `mania-v1-pre-filename-id-fix`
directory is never consulted.

The Mania analyzer is a clean-room implementation whose public design refers
to the MIT-licensed `osumania_map_analyser` documentation at commit
`f146c479fde24523b4d0909b83f8008b9d6815b2` (copyright 2026 Leo_Black). The
runtime does not embed or execute that project's JavaScript, models, or WASM;
see the pinned upstream `THIRD_PARTY_NOTICES.md` for the full provenance.

## Analyzer v4

Analyzer v4 (`five-dimension-slider-rosu-reading-v4`) keeps the five dimensions
`[Aim, Speed, Reading, Slider, Overlap]`. Aim, Speed, and Reading now come
directly from the locked `Apeuriox/rosu-pp` rework snapshot. Slider remains:

```text
0.30 * sliders / (sliders + circles)
  + 0.70 * changed consecutive slider speeds / consecutive slider transitions
```

Effective slider speed is calculated at each slider timestamp from BPM,
`SliderMultiplier`, and the active inherited timing-point SV. A map with fewer
than two sliders has a speed-change frequency of zero. The combined raw value
is quantile-normalized with the other difficulty dimensions.

Analyzer-v3 raw features, normalizers, normalized feature files, and HNSW
indexes cannot be reused because their Reading dimension used the former local
400 ms density baseline. They must be regenerated by a matching analyzer-v4
build of `osu-difficulty-lab`.

## Dynamic star-section weighting

New datasets may expose no-mod `star_rating` and fixed 0.1-star `star_section`
columns on `beatmaps`, plus versioned aggregate rows in `star_section_stats`.
The runtime reports this capability through `DatasetInfo` and can then scan the
requested buckets exactly. It derives per-dimension weights from the target's
standardized deviation from the section mean and returns the calculation as a
`DynamicWeightProfile`. Legacy datasets remain available through manual
weighting and keep the original binary feature-record layout.
